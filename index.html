Performance Killers Identified
Critical
2× Facebook Pixel Scripts
Two separate FB Pixel IDs (1104835934864266 & 921008817334240) loaded. Doubles tracking payload, increases JS execution time.
→ Fix: Consolidate into one pixel via Events Manager or use GTM to fire one.
Critical
Elementor 4.0.7 — Unoptimised CSS/JS
Elementor generates inline styles and loads global CSS for every widget. With additional_custom_breakpoints enabled, CSS output multiplies significantly.
→ Fix: Enable Elementor's "Improved CSS Loading" + "Optimized DOM". Use a caching plugin (WP Rocket/LiteSpeed). Minify/combine Elementor CSS.
High
Google Tag Manager (GTM-PQ97GVJP) Blocking
GTM loaded in <head> without async optimisation. All tags inside fire synchronously affecting FCP.
→ Fix: Audit GTM tags, add async loading, defer non-essential tags. Use Partytown for 3rd-party isolation.
High
Mixed Image Formats (webp, avif, png, jpg)
Good use of .webp and .avif in some areas, but many images still use .png and .jpg. No evidence of lazy loading attribute on all images.
→ Fix: Convert all images to WebP/AVIF. Add loading="lazy" to all below-fold images. Add explicit width/height to prevent CLS.
Medium
Google Fonts Loaded via CSS @import
Font display swap is enabled (good), but fonts are loaded via external CDN adding DNS lookup and connection overhead to render path.
→ Fix: Self-host Google Fonts. Preload critical font files with <link rel="preload">.
Medium
No Evidence of CDN
Images served directly from newgenpharmacy.co.uk origin. No Cloudflare, Fastly or similar CDN detected. London-based users OK but wider UK users suffer.
→ Fix: Enable Cloudflare (free tier) or CloudFront. This alone can improve TTFB by 200–400ms.
